## 난이도 = 성취수준 (임의 판단 금지)

아래 성취기준마다 A/B/C 성취수준을 적어두었다. 그것을 그대로 난이도로 쓴다.

| 성취수준 | difficulty | 성격 |
|---|---|---|
| C | easy | 구체적·직접 확인 수준 |
| B | medium | 개념 이해·적용 |
| A | hard | 설명·응용·복합 |

**성취기준 1개당 각 난이도 2문제씩, 총 6문제**를 만든다.
성취수준 자료가 없는 성취기준은 C/B/A를 스스로 판단해 균등하게 만든다.

## 🚫 절대 하지 말아야 할 것 (가장 중요)

이전 생성에서 실제로 나온 결함들이다. 하나라도 어기면 그 문항은 폐기 대상이다.

**1. 같은 문제를 두 번 내지 않는다**
같은 난이도의 문제들은 **서로 다른 소재·상황·묻는 방식**이어야 한다. 본문이 같거나 거의 같으면 안 된다.
- ❌ `c1` "상자, 캔, 공 중 구 모양인 것은?" (단답형) + `c2` 같은 본문 (객관식)
- ✅ `c1` "공과 같은 모양의 입체도형은?" / `c2` "교실에서 구 모양인 물건은?" / `c3` "잘 굴러가는 모양은?"

**2. 같은 문제를 단답형·객관식으로 중복 출제하지 않는다**
하나의 소재는 하나의 유형으로만 낸다.

**3. 보기 순서만 바꾼 문제를 만들지 않는다**
- ❌ `a1` 보기 [가,나,다,라] 정답2 → `a2` 보기 [라,가,나,다] 정답3
- 정답 위치 분산은 **서로 다른 문제들 사이에서** 자연스럽게 맞춘다.

**4. 본문이 제시한 선택지와 보기가 어긋나면 안 된다**
본문에서 `A, B, C 중` 처럼 범위를 좁혔으면 보기도 **그 안에서만** 나와야 한다.
- ❌ 본문 "상자, 캔, 공 중 구 모양인 것은?" → 보기 [공, 상자, 캔, **책**]  ← 책은 본문에 없다
- ✅ 보기를 4개 만들려면 본문도 4개를 제시한다 / 또는 본문에서 범위를 열어둔다

**5. 그림을 말해놓고 그림을 빠뜨리지 않는다**
본문에 `아래 그림`, `다음 표`, `아래 시계` 같은 말이 있으면 **반드시 `svg`를 넣는다.**
넣을 수 없으면 **그런 표현을 쓰지 않고** 글만으로 풀리게 쓴다.
- ❌ "아래 그림에서 원은 어느 것인가?" + svg 없음 → 학생이 절대 못 푼다

**6. 같은 SVG를 여러 문항에 재사용하지 않는다**

### 필드 규칙

| 필드 | 필수 | 규칙 |
|---|---|---|
| id | 필수 | `국어-고(선택)-{성취기준코드}-{수준소문자}{번호}`. 전체에서 유일 |
| subject / gradeBand / unit | 필수 | meta와 동일하게 고정 (`unit`은 **"문학"**) |
| standard | 필수 | 성취기준 코드 (대괄호 없이) |
| level | 필수 | A / B / C |
| difficulty | 필수 | easy / medium / hard (위 표대로) |
| type | 필수 | multiple 또는 short |
| body | 필수 | 문제 본문 |
| options | 객관식만 | 정확히 4개. 본문이 제시한 범위 안에서만 |
| answer | 객관식만 | 0~3 정수 |
| answers | 단답형만 | 허용 정답 배열. 동의어·띄어쓰기 변형 포함 |
| why | 필수 | 한 줄 해설 |
| svg | 선택 | 아래 규칙. 본문이 그림을 언급하면 **필수** |
| passage | 선택 | 지문을 읽고 푸는 문제면 `passages`의 `id`. 아니면 넣지 않는다 |

`passages` 의 각 지문:

| 필드 | 필수 | 규칙 |
|---|---|---|
| id | 필수 | `p1`, `p2` … 파일 안에서 유일 |
| title | 필수 | 지문 제목 (작품명 또는 글의 제목) |
| text | 필수 | 지문 본문. 문단은 `\\n\\n` 으로 나눈다 |
| source | 필수 | 출처. 아래 '지문 규칙' 참고. **절대 비우지 않는다** |
| svg | 선택 | 지문에 딸린 표·그래프 (SVG 규칙과 같음) |

지문이 필요 없는 영역이면 `"passages": []` 로 둔다.

## 평가 불가능한 성취기준

실기·수행·태도 중심이라 글로 된 4지선다·단답형으로 평가할 수 없는 성취기준은
억지로 만들지 말고, `skipped` 배열에 `{"standard":"코드","reason":"이유"}` 로 보고한다.

## 출제 품질 규칙

1. 오답 보기는 학생이 실제로 저지르는 실수·오개념에서 만든다. 무의미한 보기 금지
2. 정답 위치를 0,1,2,3에 고르게 분산한다 (단, 보기 회전은 금지 — 위 3번 참고)
3. 해당 학년이 이해할 수 있는 어휘만 쓴다
4. 보기 4개의 길이와 형식을 비슷하게 맞춘다 (정답만 길면 티가 난다)
5. 단답형은 정답이 한 단어~짧은 구여야 하고, answers에 허용 표현을 모두 넣는다
6. 전체 문제 중 단답형은 2~3할 정도만 섞는다
7. 특정 지역·성별·가정환경을 전제하지 않는 중립적 소재를 쓴다

## 지문 규칙 (긴 글·자료를 읽고 푸는 문제)

글을 읽어야 풀 수 있는 문제는 글을 문제 본문에 넣지 말고 **`passages`에 지문으로 따로** 넣는다.
앱은 지문을 먼저 보여 주고(시간 제한 없이 읽기), 다 읽으면 문제와 타이머가 나온다.
같은 지문의 문제들은 이어서 나오므로 학생은 한 번 읽고 여러 문제를 푼다.

이 영역의 지문 비중 → **높음** — 문항의 절반 이상을 지문 문제로 만든다 (작품·글을 읽고 푸는 영역)

**만드는 법**
- 지문 하나에 문제 **2~4개**를 붙인다 (지문 하나에 문제 하나는 피한다)
- 한 지문에 붙은 문제들은 서로 다른 것을 묻는다 (중심 내용 / 세부 내용 / 어휘 / 추론 / 표현 방법 …)
- 문제 본문(body)에 지문을 다시 옮겨 적지 않는다. "이 글에서 …" 처럼 지문을 가리키기만 한다
- 지문 하나에 붙은 문제들도 성취기준·난이도 규칙(성취기준당 난이도별 개수)을 그대로 따른다

**길이 (공백 포함 글자 수)** — 학년에 맞춘다
- 초1-2: 100~300자 · 초3-4: 200~500자 · 초5-6: 300~700자 · 중학교: 400~900자 · 고등학교: 500~1200자
- 앱은 기본으로 **(지문 + 문제)가 800자 이하인 것만 배틀**에 내고, 더 긴 것은 '문제풀이'에서만 낸다.
  그러니 **대부분은 800자 안쪽**으로 쓰고, 긴 글이 꼭 필요할 때만 길게 쓴다
- 상한 3,000자

**출처 (`source`) — 반드시 적는다**
- 직접 지은 글: `직접 지음`
- 교과서에 실린 작품·글: 작품명·지은이·실린 교과서를 적는다
  - 예: `윤동주, 「서시」` / `김소월, 「엄마야 누나야」 (국어 5-1 가)` / `전래 동화 「해와 달이 된 오누이」`
- 교과서 글은 **원문을 정확히 알고 있을 때만** 그대로 싣는다.
  원문이 확실하지 않으면 **지어내거나 바꿔서 원작자 이름을 붙이지 말고**, 같은 주제로 새 글을 쓰고 `직접 지음`으로 적는다
- 실존 인물·기관이 쓴 것처럼 꾸민 글을 만들지 않는다
- 시·노래 가사처럼 짧은 작품은 전문을, 긴 작품은 필요한 부분만 싣는다 (`… 중에서`를 출처에 붙인다)

**하지 말 것**
- ❌ 지문에 없는 내용을 묻는 문제 / 지문만 읽어서는 답이 둘 이상 나오는 문제
- ❌ 지문 안에 정답을 그대로 표시(굵게·괄호)해 두는 것
- ❌ 쓰지 않는 지문 (모든 지문에 문제가 1개 이상 붙어야 한다)

## SVG 규칙 (그래프·도형·표)

그림이 필요한 문제는 `svg` 필드에 직접 그려 넣는다. 외부 이미지는 절대 쓰지 않는다.

**얼마나 넣나**
- 도형·측정·자료·그래프처럼 **시각 자료가 본질인 영역은 문항의 절반 이상**에 넣는다
- 그 외에도 그림이 있으면 이해가 쉬워지는 문항에는 적극적으로 넣는다
- 글만으로 충분한 문항에는 넣지 않는다 (억지로 넣지 말 것)

**필수**
- `viewBox`를 반드시 지정: `<svg viewBox="0 0 160 80">`
- `width` / `height` 고정값 금지 (반응형이어야 함)
- 하나당 8KB 이내
- 글자 `font-size`는 12 이상, 선 `stroke-width`는 2 이상 (작은 화면 대비)
- 다크 모드 대비: 배경을 칠하지 말고 선·글자에 `stroke="currentColor"` `fill="currentColor"` 사용.
  강조색이 필요하면 `#4b7bec`(파랑), `#e07b39`(주황)만 쓴다

**금지**
- `<script>`, `onclick` 등 이벤트 속성 / `<foreignObject>` / 외부 이미지 `href`
- 색만으로 정보를 구분하는 것 (색약 학생 배려 — 무늬·라벨·모양을 함께 쓴다)
- **같은 SVG를 다른 문항에 재사용**

권장 소재: 막대·꺾은선·원그래프, 좌표평면, 수직선, 도형과 치수, 각도, 분수 모형, 시계, 자, 표, 회로도

## 결과를 파일로 저장

- 파일명: **`bank_국어_문학_01_1.json`** ← 이 이름을 그대로 쓴다
- 형식 `.json` / 인코딩 **UTF-8 (BOM 없이)** / 줄바꿈 LF
- 파일 안에는 JSON 하나만. 코드펜스·설명·주석 금지
- 한글을 `\uXXXX` 로 이스케이프하지 말고 그대로 쓴다

저장 후 **채팅창에는 전체 JSON을 출력하지 말고** 아래만 보고한다.
- 파일명과 총 문항 수 / 난이도별 개수 / 객관식·단답형 개수 / SVG를 넣은 문항 수
- 지문 개수 / 지문 문제 수 / 지문별 글자 수 / 출처 목록
- `skipped` 목록과 이유 / 자체 점검 결과

## 출력 전 자체 점검 (반드시 수행)

- [ ] JSON이 문법적으로 유효한가
- [ ] 모든 `id`가 유일한가
- [ ] **같은 본문의 문제가 두 개 이상 있지 않은가** ⭐
- [ ] **보기 순서만 다른 문제 쌍이 없는가** ⭐
- [ ] **본문이 제시한 선택지 범위와 보기 4개가 일치하는가** ⭐
- [ ] **본문이 그림을 언급한 문항에 모두 `svg`가 있는가** ⭐
- [ ] **같은 `svg`를 재사용한 문항이 없는가** ⭐
- [ ] 객관식의 `options`가 정확히 4개이고 `answer`가 0~3인가
- [ ] `difficulty`가 `level`과 대응하는가 (C=easy, B=medium, A=hard)
- [ ] 성취기준 1개당 6문제(난이도별 2개)가 있는가
- [ ] LaTeX 백슬래시가 두 번(`\\`)으로 이스케이프되었는가
- [ ] SVG에 `viewBox`가 있고 금지 요소가 없는가
- [ ] **모든 `passage` 값이 `passages`의 `id`와 맞는가** ⭐
- [ ] **모든 지문에 `source`(출처)가 있는가** ⭐
- [ ] 모든 지문에 문제가 2개 이상 붙어 있는가 (쓰지 않는 지문이 없는가)
- [ ] 문제 본문(body)에 지문을 다시 옮겨 적지 않았는가
- [ ] 아래 제시된 성취기준 범위 밖의 내용이 섞이지 않았는가

이제 위 조건에 맞춰 JSON만 출력하라.

## 대상 성취기준 (원문)

### 12문학01-01
문학이 인간과 세계에 대한 이해를 돕고, 삶의 의미를 깨닫게 하며, 정서적⋅미적으로 삶을 고양함을 이해한다.
